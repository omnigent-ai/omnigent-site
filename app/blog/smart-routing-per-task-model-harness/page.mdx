If you run several coding agents in Omnigent and don't always know which one to
reach for, you can now let the server choose. Pick **Auto** in the harness
picker and Smart Routing reads your first message, then decides which harness
and model fit the task and keeps the session there.

Committing to one model before you know what a task needs means a quick edit
lands on the same heavyweight setup as a multi-file refactor, and switching
panes afterward is manual. Smart Routing removes that guess: the server asks a
router "given this task, which harness and model fit?" and applies the answer
for the rest of the session, so each job runs where it belongs without you
sorting it out first.

To turn it on, choose Auto in the harness picker; routing then happens on your
first message. Enabling it is configuration only. A server `llm:` block gives
you the built-in judge with no extra infrastructure, or a `routing:` block with
`provider: external` delegates the decision to your own routing service. Start
the server with your config file:

```
omni server -c path/to/config.yaml
```

If an external router is configured but unavailable, routing falls back to the
built-in judge instead of dropping the session off Auto. See the
[Smart Routing guide](/docs/build/routing) for the full setup and the external
routing API.
