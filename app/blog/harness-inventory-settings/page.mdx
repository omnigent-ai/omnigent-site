If you run Claude Code, Codex, or another coding agent through Omnigent on more
than one machine, you can now see what each of them already has set up without
opening a terminal on that machine. Settings › Harnesses shows, per host and per
harness, the MCP servers, skills, and plugins that agent brings with it.

Until now that inventory lived in scattered config files on each laptop or
sandbox, and the only way to check "does this host's Claude have the Figma
plugin?" was to go look. Now you pick a machine, open a harness card, and read
the answer. Expand an MCP server to see the tools it offers and whether it
connects; open a skill to read its instructions; open a plugin to see its
version, marketplace, enabled state, and the skills and MCP servers it bundles.
For Claude Code and Codex, a read-only Settings tab also shows which binary the
host launches and how many startup arguments it is configured with. Everything
is read from the host on demand and only summaries reach the server: raw
config, argument values, and secrets stay on the machine.

Open Settings › Harnesses, choose a host, and click a configured harness (or its
gear icon to land on launch settings). The same inventory also appears when a
new machine connects: a one-time review dialog lists the logins, MCP servers,
skills, and plugins its harnesses bring over, and you can reopen it any time
from Settings › Import with "Review imports". The page is a gated release
feature; an operator enables it deployment-wide by adding `harness_settings_ui`
to the server's release features:

```bash
OMNIGENT_FEATURES=harness_settings_ui
```

See the [Web UI guide](/docs/interact/web-ui) for how release features are
enabled and for the rest of the Settings pages.
