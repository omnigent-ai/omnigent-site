# v0.16.0

_Released 2026-09-29_ · Omnigent maintainers

Omnigent 0.16.0 updates the workspace browser, sandbox controls, and agent configuration. It also improves runner reconnection and harness reliability. Review the breaking changes below before upgrading.

## Major new features

### Unified workspace browser and file panel

A unified workspace browser and compact file panel show badges for added, modified, and deleted files. Shared controls and folder indicators make changes easier to find while navigating the workspace.

The desktop app adds Show in Finder for local files and an opt-in setting to open chat links in the in-app browser. Embedded browser sites can request local network access through a Chrome-style permission prompt.

![The unified workspace browser](https://github.com/user-attachments/assets/a84ab68d-a958-40b6-8178-ea0e7bc03c87)

([#8254](https://github.com/omnigent-ai/omnigent/pull/8254), [#8335](https://github.com/omnigent-ai/omnigent/pull/8335), [#6691](https://github.com/omnigent-ai/omnigent/pull/6691), [#8219](https://github.com/omnigent-ai/omnigent/pull/8219), [#8049](https://github.com/omnigent-ai/omnigent/pull/8049), [@ajayalfred](https://github.com/ajayalfred), [@nakazax](https://github.com/nakazax), [@fanzeyi](https://github.com/fanzeyi))

### Sandbox edits and repository clones

Linux agents can make disposable edits by setting `copy_on_write: true` on a sandbox `write_paths` entry. Edits stay in a disposable layer while the underlying files remain unchanged.

Admins can opt into shallow clones to limit history or blobless clones to fetch file contents on demand. Daytona sessions also keep their workspace when a stopped or archived sandbox resumes.

Learn more about [filesystem access](/docs/reference/configuration/os-sandbox#filesystem) and [Git clone options](/docs/reference/configuration/cloud-sandbox#git-clone-options).

([#7599](https://github.com/omnigent-ai/omnigent/pull/7599), [#8322](https://github.com/omnigent-ai/omnigent/pull/8322), [#7828](https://github.com/omnigent-ai/omnigent/pull/7828), [@mxatone](https://github.com/mxatone), [@dhruv0811](https://github.com/dhruv0811), [@wilbeibi](https://github.com/wilbeibi))

### Admin defaults for sharing, allowed origins, and Slack setup

Settings > Sharing now lets admins default new sessions to public, choosing off, sandbox-only, or all sessions.

`OMNIGENT_WS_ALLOWED_ORIGINS` accepts `*.` entries to trust all subdomains of a domain. Operators can also pre-select the Slack setup agent and managed host through `OMNIGENT_SLACK_DEFAULT_AGENT_ID` and `OMNIGENT_SLACK_DEFAULT_HOST_TYPE`; users can change those choices before submitting setup.

![Settings > Sharing with the default visibility controls](https://github.com/user-attachments/assets/50159570-0d4a-4f11-84cc-3dc9ceafaffc)

Learn more about [session sharing](/docs/collaborate/auth#session-sharing) and [Slack setup defaults](/docs/interact/slack#operator-set-setup-defaults).

([#8295](https://github.com/omnigent-ai/omnigent/pull/8295), [#8070](https://github.com/omnigent-ai/omnigent/pull/8070), [#6965](https://github.com/omnigent-ai/omnigent/pull/6965), [@dhruv0811](https://github.com/dhruv0811), [@natsuskaizen](https://github.com/natsuskaizen), [@bdchatham](https://github.com/bdchatham))

### Pi prompt controls and native images

Pi agents can set `executor.context_files: false` to skip automatically discovered context files while keeping their explicit instructions. With the regular Pi harness, `executor.system_prompt_mode: replace` replaces Pi's base system prompt with the agent's Omnigent instructions. Framework instructions remain in place, and skills and extensions can still contribute to the final prompt.

MCP tool images and embedded-browser screenshots now reach supported harnesses as native images with accompanying text.

Learn more about the [system prompt](/docs/build/prompts#system-prompt).

([#8184](https://github.com/omnigent-ai/omnigent/pull/8184), [#8349](https://github.com/omnigent-ai/omnigent/pull/8349), [#7444](https://github.com/omnigent-ai/omnigent/pull/7444), [@PattaraS](https://github.com/PattaraS), [@Jomak-x](https://github.com/Jomak-x))

## Breaking changes

- Saved preferences and inference snapshots are now capped at 65,535 stored bytes: upgrading resets oversized preferences to defaults and clears snapshots that remain oversized after compression, and new oversized project-order saves or snapshots are rejected before session creation ([#8137](https://github.com/omnigent-ai/omnigent/pull/8137), [#8143](https://github.com/omnigent-ai/omnigent/pull/8143), [@dbczumar](https://github.com/dbczumar))
- Only session owners can manage MCP servers or replace agent bundles; collaborators who previously edited MCP configuration now get read-only visibility and must ask the owner to make changes ([#8481](https://github.com/omnigent-ai/omnigent/pull/8481), [@dhruv0811](https://github.com/dhruv0811))

## Bug fixes

- 🔌 Brief runner drops (Wi-Fi roam, VPN stall, sleep/resume, replica failover) no longer fail turns with "Runner disconnected unexpectedly", runners reconnect promptly, and host launches no longer spawn duplicate runners ([#8093](https://github.com/omnigent-ai/omnigent/pull/8093), [#8094](https://github.com/omnigent-ai/omnigent/pull/8094), [#8152](https://github.com/omnigent-ai/omnigent/pull/8152), [#8413](https://github.com/omnigent-ai/omnigent/pull/8413), [#8085](https://github.com/omnigent-ai/omnigent/pull/8085), [@yaoharry](https://github.com/yaoharry), [@dbczumar](https://github.com/dbczumar), [@daniellok-db](https://github.com/daniellok-db))
- 🖥️ Codex terminals recover without restarting a healthy backend, keep their final screen and exit code, survive launcher sign-in prompts with the link shown in chat, and cold resumes no longer lose tool results across compaction; sub-agents no longer flash "failed" on newer Codex versions ([#7442](https://github.com/omnigent-ai/omnigent/pull/7442), [#8233](https://github.com/omnigent-ai/omnigent/pull/8233), [#8040](https://github.com/omnigent-ai/omnigent/pull/8040), [#8271](https://github.com/omnigent-ai/omnigent/pull/8271), [#8309](https://github.com/omnigent-ai/omnigent/pull/8309), [@yaoharry](https://github.com/yaoharry), [@dbczumar](https://github.com/dbczumar))
- 🤖 Claude Code sessions use a Unix socket instead of a loopback port per MCP helper, treat `/exit` as a clean stop, show Claude's own API error text, aren't failed by a background sub-agent, and mark lost messages undelivered instead of duplicating the next one ([#8079](https://github.com/omnigent-ai/omnigent/pull/8079), [#8364](https://github.com/omnigent-ai/omnigent/pull/8364), [#8097](https://github.com/omnigent-ai/omnigent/pull/8097), [#8103](https://github.com/omnigent-ai/omnigent/pull/8103), [#8186](https://github.com/omnigent-ai/omnigent/pull/8186), [@dbczumar](https://github.com/dbczumar), [@yaoharry](https://github.com/yaoharry))
- 🧠 Pi on the Databricks AI Gateway lists Claude, OpenAI, and Gemini models, sub-agents no longer report false launch failures, and new sessions accept the first message during provider setup ([#8228](https://github.com/omnigent-ai/omnigent/pull/8228), [#8200](https://github.com/omnigent-ai/omnigent/pull/8200), [#8424](https://github.com/omnigent-ai/omnigent/pull/8424), [@dbczumar](https://github.com/dbczumar), [@serena-ruan](https://github.com/serena-ruan))
- ✍️ Composer fixes: cancel or edit an unsent message while a model switch finishes, pick skills with `/` anywhere in a prompt, and Files panel search finds tracked files in repositories of any size ([#8039](https://github.com/omnigent-ai/omnigent/pull/8039), [#8087](https://github.com/omnigent-ai/omnigent/pull/8087), [#8409](https://github.com/omnigent-ai/omnigent/pull/8409), [@dbczumar](https://github.com/dbczumar), [@serena-ruan](https://github.com/serena-ruan))
