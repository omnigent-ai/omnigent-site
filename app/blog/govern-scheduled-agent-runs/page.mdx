If you run agents on a schedule (a nightly triage, a recurring report, a
weekday cleanup), you can now put two guardrails on each run: a cost cap and a
permission mode. Both live on the scheduled task itself, so every firing
inherits them without you watching the clock.

Unattended runs are where surprises hurt most. A loop that misbehaves at 3am
can burn through spend before anyone notices, and a coding agent left to its
own devices might take actions you never wanted it to take on its own. Setting
a per-firing budget stops a run once its cumulative spend reaches your limit,
and setting a permission mode decides up front how much the agent may do
without asking.

Set a budget with `max_cost_usd` when you create or update a scheduled task.
Once a firing reaches that number, all models are blocked for the rest of that
run; leave it unset for no cap, or clear it later to remove the cap. For a
Claude Code task you can also set `permission_mode` per task, choosing from
`default`, `auto`, `acceptEdits`, `plan`, `dontAsk`, and `bypassPermissions`,
so an unattended run can proceed on its own or hold back exactly as you decide.

```
max_cost_usd: 5.0
permission_mode: acceptEdits
```

The permission mode applies to Claude Code tasks; other agents keep their own
defaults. See the [scheduled tasks guide](/docs/build/scheduled-tasks) for how
to create and manage a task.
