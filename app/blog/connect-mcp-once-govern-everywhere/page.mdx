If your agents move between your laptop, remote hosts, and sandboxes, you can
now connect an MCP account like your issue tracker or Databricks workspace one
time and use its tools on any of them.

Until now, every new machine or sandbox meant setting up the same MCP servers
and signing in again. Now an administrator lists the approved services and the
tools each one may expose. You sign in once in **Settings → MCP**, and the
Omnigent server keeps and refreshes your credentials. Sessions only get a
reference to the service, so tokens never reach the machine the agent runs on.
Every tool call goes through the server and the same session policies as the
rest of your agent's work. Tools the administrator left off the list never show
up, and calls to them are rejected. If you replace a sandbox, start a session
on the new one, turn the same service back on, and it works without signing in
again.

To try it, open **New session** and click **MCPs** in the workspace bar above
the composer. Turn on the services you want in **Tools for this session**. If a
service isn't connected yet, a sign-in popup opens and the service turns on once
you approve it. Then pick a host or a new sandbox, an agent, and your first
message, and launch. The first turn can already use the tools. Turning a service
off only removes it from that session, and your account stays connected. The
composer also remembers your picks for the next new session in this browser.
You can also add services to an existing session from **Agent tools and
policies** and then restart it to load them. To set up the registry, follow the
[MCP registry walkthrough](https://github.com/omnigent-ai/omnigent/blob/main/examples/mcp-registry/README.md).
