If you use Cognition's Devin CLI, you can now run it as a native Omnigent
harness. Devin keeps its own terminal, its own login, and its own models, and
Omnigent wraps it with the same policies, approval cards, and session tree you
already use for Claude Code, Codex, and the rest.

Until now, Devin ran through Omnigent's generic ACP path, which meant no policy
enforcement, no mid-session model changes, and no view into the delegates Devin
spins up. `omnigent devin` replaces that. The real Devin TUI runs in an embedded
terminal and is mirrored into Chat. Every tool call passes through your Omnigent
policies before it runs, and a deny sticks even when Devin is in bypass mode.
Devin's own consent prompts show up as approval cards in Chat, so nothing is
stranded in a pane nobody is watching. You can switch model, effort, and
permission mode while a run is in progress, Devin gets Omnigent's MCP tools, and
each `run_subagent` delegate appears as its own child session with its own
transcript and cost once it finishes. Messages you send while Devin is working
steer the current turn instead of waiting behind it.

Install the Devin CLI, sign in with it (Omnigent stores no Devin credential),
and start a session:

```bash
curl -fsSL https://cli.devin.ai/install.sh | bash
devin auth login
omnigent devin
```

Model and effort are separate flags, and Omnigent composes them into the model
id Devin expects:

```bash
omnigent devin --model opus --effort xhigh
```

In the web UI, pick Devin in New Chat and choose a model family from the picker.
If you pick Fusion, the picker lets you choose the lead model and its sidekick
separately. The earlier ACP-based Devin integration is retired, and existing
references to it resolve onto the native harness. See the
[Devin section of the harness configuration docs](/docs/build/harnesses/configuration#devin)
for setup details.
