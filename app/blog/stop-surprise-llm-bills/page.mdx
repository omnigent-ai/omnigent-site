As AI coding assistants become essential, **surprise LLM bills blow through monthly budgets**. One debugging session or multi-agent workflow gone wrong, and costs spiral.

Unlike traditional software, LLM expenses scale with _token consumption_. Every character costs money. Long conversations accumulate context, multi-agent workflows amplify usage, and hard budget caps interrupt productive flow. Many teams discover their bills only after the fact.

**Omnigent's four-layer solution:**

1. **Prevention**: Smart routing blocks trivial tasks from expensive models
2. **Control**: Progressive budgets with soft warnings and smart downgrade gates
3. **Visibility**: Real-time cost tracking with detailed breakdowns
4. **Safeguards**: Thrashing detection, scheduled task limits, terminal approvals

## Smart Task Routing: Prevention First

The most effective cost optimization prevents wasteful spend before it happens. Omnigent's **smart routing policy** classifies user messages as TRIVIAL or COMPLEX and denies trivial tasks from using expensive models.

### How It Works

When a session attempts to use an expensive model (Opus, Fable, GPT-5), Omnigent classifies the user's message using a lightweight LLM:

```yaml
policies:
  trivial_gate:
    type: function
    function:
      path: omnigent.policies.builtins.routing.deny_trivial_to_expensive_model
      arguments:
        expensive_models: ["opus", "fable", "gpt-5"]
```

**Classification categories:**

- **TRIVIAL tasks** (blocked on expensive models): Simple factual lookups, greetings and status checks, trivial code changes, short Q&A
- **COMPLEX tasks** (allowed on any model): Multi-step reasoning, complex code analysis, open-ended research, nuanced architecture decisions

**Example flow:**

```
User: "Fix the authentication bug in login.py"
→ Classifier: COMPLEX
→ Opus request: ALLOWED

User: "What's the current time?"
→ Classifier: TRIVIAL
→ Opus request: DENIED
→ User switches to Haiku
```

By preventing trivial tasks from using expensive models, smart routing can **significantly reduce Opus/Fable usage** with no loss in quality for complex work. Learn more in the [Omnigent Routing documentation](https://omnigent.ai/docs/build/routing).

## Progressive Budget Policies

Smart routing reduces expensive model calls, but production workflows still consume resources. Omnigent's [contextual policy system](/blog/omnigent-policies) provides **progressive cost controls** with soft warnings before hard limits.

### Session Cost Budget

```yaml
policies:
  cost_budget:
    type: function
    function:
      path: omnigent.policies.builtins.cost.cost_budget
      arguments:
        max_cost_usd: 5.0
        ask_thresholds_usd: [1.0, 2.5]
        expensive_models: ["opus", "fable", "gpt-5"]
```

**Soft thresholds** provide progressive warnings at $1 and $2.50. **Each checkpoint prompts at most once** after approval, future turns don't re-prompt until the next threshold.

**Hard limit** at $5 is a **smart downgrade gate**: blocks expensive models but allows work to continue on cheaper tiers (Sonnet, Haiku).

### Per-User Daily Cost Budget

For organizations managing multiple developers, **per-user daily budgets** track cumulative spend across _all_ sessions for the current UTC day:

```yaml
policies:
  user_daily_cost_budget:
    arguments:
      max_cost_usd: 10.0
      ask_thresholds_usd: [3.0, 7.0]
      expensive_models: ["opus", "fable"]
```

A 5-developer startup setting `max_cost_usd: 10.0` caps monthly spend at ~$1,500 (5 × 30 × $10).

Learn more: [Omnigent Cost Budget Policies](https://omnigent.ai/docs/policies/builtin#cost_budget)

## Custom Pricing for Self-Hosted Models

Teams running self-hosted models on Ollama, vLLM, or custom inference gateways previously saw "unpriced spend" warnings that disabled budget enforcement.

**Solution: Custom pricing configuration**

```yaml
providers:
  ollama-local:
    kind: local
    openai:
      base_url: "http://localhost:11434/v1"
      pricing:
        input_per_million: 0.0
        output_per_million: 0.0

  vllm-gateway:
    kind: remote
    openai:
      base_url: "https://inference.company.internal/v1"
      pricing:
        input_per_million: 0.25
        output_per_million: 1.0
```

This eliminates "unpriced spend" warnings while enabling accurate budget enforcement. Use cases include cost attribution for self-hosted models, free local development, and internal chargeback.

## Cost Optimization Through Model Selection

### Sticky Model Choices

The composer remembers your model choice per harness, so once you switch from an expensive model to a cheaper one, that choice becomes your default for future sessions with that harness.

**Example impact:**

A 10-developer team working on routine coding tasks:

- **Before**: Sessions defaulted to Opus ($15/million output tokens)
- **After**: Team switches to Sonnet ($3/million output tokens) for most work
- **Result**: **80% cost reduction** for routine coding tasks
- **Flexibility**: Can still override to Opus for complex tasks when needed

In the New Chat composer, select your model from the dropdown. Your choice is remembered per harness (Claude Code, Codex, etc.), making it easy to establish cost-effective defaults across your team while maintaining flexibility for work that needs more capable models.

## Cost Visibility: Know Where Tokens Go

### Usage Page

The Usage page (`/usage`) provides comprehensive LLM spend analytics:

1. **Daily Cost Timeline**: Bar chart with gap-filling for zero-spend days
2. **Cost by Harness**: Which execution environments consume budget
3. **Cost by Model**: Which tiers drive spend (Opus vs Sonnet vs Haiku)
4. **Sortable Session Table**: Title, harness, model, cost, last active

### Multi-Model Session Display

Sessions that switch models now show **all models used**:

```
Session: "Debug authentication flow"
Model: claude-opus-4 +2
```

Hovering `+2` reveals additional models sorted by cost, answering "Why did this cost $3 when I thought I was on Sonnet?"

### Sub-Agent Harness Visibility

Multi-harness workflows display which execution environments were used:

```
Harness: claude-code-native +1
→ Hover: "Sub-agents also used: antigravity"
```

Essential for organizations using multiple AI providers (Anthropic, OpenAI, Gemini).

## Safeguards & User Experience

### Native Terminal Cost Popups

Interactive approval popups rendered via `tmux display-popup`:

```
┌───────────────────────────────────────────────┐
│  ⚠️  Policy approval required                 │
│                                               │
│  Session cost $1.05 passed the $1.00          │
│  warning threshold (limit $5.00).             │
│                                               │
│  [y] approve    [n] decline                   │
└───────────────────────────────────────────────┘
```

Multi-surface approval: popup and web UI resolve the same elicitation, whichever answers first wins.

### Scheduled Task Cost Budgets

Unattended tasks automatically attach cost budgets:

```json
POST /v1/scheduled-tasks
{
  "title": "Daily code review",
  "schedule": "0 9 * * *",
  "max_cost_usd": 2.0
}
```

Prevents a single cron run from consuming $50 due to an unexpected large diff.

### Detect Thrashing Policy

Identifies agents stuck in retry loops via pattern matching:

- Consecutive errors (default: 5 failures)
- Error rate (default: 80% over 10 results)

**Cost impact**: Prevented runaway sessions that would have consumed $10+ before exhausting retries.

Learn more: [Omnigent Detect Thrashing Policy](https://omnigent.ai/docs/policies/builtin#detect_thrashing)

### Archived Session Retention

Configurable auto-cleanup of archived sessions (7/30/60/90 days) via Settings → Archived sessions. Reduces storage costs and UI clutter for high-volume teams.

**Example**: A 50-person team archiving ~200 sessions monthly maintains steady state of ~400 sessions (60-day retention) instead of 2,400 accumulating annually.

## Putting It All Together

Omnigent's cost optimization features address LLM expenses at multiple layers:

**Prevention (Layer 0):**

- Smart routing blocks trivial tasks from expensive models
- Sticky model selection makes switching to cheaper tiers persistent (e.g., Opus→Sonnet = 80% cost reduction)
- No workflow changes required

**Control (Layer 1):**

- Progressive budgets: soft warnings → hard limits → smart downgrade gates
- Multi-granularity: session-level and user-daily scopes
- Custom pricing for self-hosted models enables accurate enforcement
- Scheduled task limits prevent unattended runaway costs

**Visibility (Layer 2):**

- Usage page with daily timelines and breakdowns by harness/model
- Multi-model and multi-harness session tracking
- Real-time visibility prevents end-of-month surprises

**Safeguards & Lifecycle (Layer 3):**

- Native terminal popups for in-terminal approval
- Thrashing detection prevents wasteful retry loops
- Archived session retention with configurable auto-cleanup
- Date range validation and UX polish

1. **Progressive, not binary**: Soft warnings before hard stops, downgrade gates instead of full blocks
2. **Multi-layered**: Routing + sticky model selection + budgets + visibility working together
