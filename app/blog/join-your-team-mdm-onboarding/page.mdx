If you run Omnigent for a team and hand out company Macs through MDM, new
teammates can now get from a fresh desktop install to a working session with
one click. The welcome screen shows a single **Join your team** button, labeled
with your server's name, and the rest of setup follows from it.

Before this, every new person had to know the server URL, type it in, sign in,
and then work out how to connect a runner on their own. Now the app reads the
server your organization publishes through macOS Managed Preferences and asks
one question: where do you work today? Pick a remote environment, if your
server offers one, or **My laptop** (the card explains that the server will be
able to run agents on it). **Install Omnigent** then installs anything missing,
connects the runner you chose, shows progress while it signs in and opens the
server, and you can cancel at any point. Your first new-session screen opens
with that runner preselected, so the only thing left to do is start a chat.

Nothing is forced on anyone. The button's dropdown still lists your other
managed servers, recent servers, and a field for any server URL. To set it up,
publish your server list through MDM under the `ai.omnigent.desktop` domain and
give each server a display name with an `omnigentServerName` query parameter
(Omnigent strips it before connecting). The first server's name becomes the
button label.

```xml
<key>serverUrls</key>
<array>
  <string>https://omnigent.corp.example.com/?omnigentServerName=Engineering</string>
</array>
```

Server operators can also name a deployment from the server side with
`branding.server_name` in the server config; the desktop app shows that name
next to the host wherever it lists servers, and an MDM-provided name wins when
both are set.

```yaml
branding:
  server_name: "Acme Engineering"
```

Managed servers are read on macOS. See the
[desktop app guide](/docs/interact/desktop#managed-servers-macos-mdm) for the
full preference reference and an example MDM profile.
