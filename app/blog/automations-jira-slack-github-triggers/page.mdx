If your team files bugs in Jira, asks questions in Slack, or opens GitHub
issues, you can now have Omnigent pick up each new one and start an agent
session for it on its own. Nobody has to copy a ticket into a chat first.

You describe the trigger in a short sentence, such as "Ticket created in
project equals ES, and Label equals bug, then Comment the session link on the
ticket", and add the instructions each session should follow ("Investigate
the ticket and propose a fix"). Every hour, the automation looks for new
matches and starts one session per ticket, message, or issue, on a host you
pick or in a fresh sandbox. Each session knows no one is watching, so it works
toward the goal instead of stopping to ask questions. If you turn on link-back,
the session link is posted on the original item, and anything the agent posts
ends with a "Sent with Omnigent" line so your teammates can tell where it came
from.

To set one up, open **Automations** from the sidebar and switch to the
**Templates** tab. Pick **Jira tickets**, **Slack messages**, or **GitHub
issues**, fill in the project, channel, or repository, add any conditions, and
save. The agent needs a way to reach the service where the automation runs: a
Jira or Slack MCP server, or for GitHub the GitHub CLI or a GitHub MCP server.
The form warns you if that is missing. Open **Preview prompt** to read exactly
what the agent will be told, or **Edit as prompt** to fine-tune it as text. For
how automations run, see the
[scheduled tasks guide](/docs/build/scheduled-tasks).
