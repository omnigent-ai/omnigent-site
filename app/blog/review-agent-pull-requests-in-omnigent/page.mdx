If your agents open pull requests that touch dozens of files, you can now work
through the whole diff in Omnigent and keep track of what you have already read.

A large agent PR is hard to review in one sitting. You lose your place, and when
the agent pushes a fix you can't tell which files you need to look at again. The
**Changes** tab now tracks that for you. Tick **Viewed** on a file and it
collapses, and a progress row shows how far along you are (for example
`12 / 30 files viewed`). Turn on **Hide viewed** to see only what's left. Your
marks are saved in your browser, so they're still there after a reload. When the
agent pushes new commits, files whose changes are untouched stay marked. Files it
changed lose their mark, show **Changed since viewed**, and open again for you.

Other tools in the tab help you find your way around. **Filter changed files**
narrows the list by path. Cmd/Ctrl+F searches the fetched diff and opens
collapsed files to show each match. Each file header can copy the file's path
or open the file on your Git provider at the revision you are reviewing. On
GitHub pull requests, switch the toolbar to **Commits** to see the PR's history
oldest first. Search it by sha, title, or author, open any commit's diff, and
move through them with **Previous commit** and **Next commit**.

To try it, open a coding-agent session that has a pull request, expand
**Workspace** in the rail, choose **Pull Requests**, and open **Changes**. On
desktop you can also click the PR link in the composer. On a phone, open the
session actions menu and choose **Pull Requests**. The
[Web UI guide](/docs/interact/web-ui#github) covers how the tab finds a
session's pull requests.
