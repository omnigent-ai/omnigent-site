# v0.16.0

_Released 2026-09-29_ · 4 min read · Omnigent maintainers

Omnigent 0.16.0 is a major release focused on smoothing the whole path from first launch to production-grade agent runs, from getting the desktop app set up and pointed at your team's server to controlling how agents edit files inside sandboxes. The desktop onboarding flow has been redesigned end to end, the workspace panel has been unified into a single browser with change badges, Linux sandboxes gain disposable copy-on-write edits and lighter repository clones, admins get new defaults for session sharing, trusted origins, and Slack setup, and Pi agent authors can take full control of their prompts while MCP tools and the embedded browser hand images to harnesses natively.

## 1. Redesigned desktop onboarding

![TODO: add a demo screenshot or GIF for "Redesigned desktop onboarding"](TODO)

Getting the desktop app from a fresh install to a working session should not take a detour through the terminal and a docs page. The redesigned onboarding detects returning users so you skip steps you have already completed, installs the CLI for you on macOS from inside the app, and walks you through the remaining steps with smoother animated transitions.

If your organization publishes preset servers, a "Join your team" path picks them up so you connect to the right server without copying URLs around. Once setup finishes, a post-setup import review shows you the existing chats it found, grouped per harness, so you can decide what to bring into Omnigent before you start working.

_Learn more in the [Get started](/docs/interact/desktop#get-started)._

## 2. Unified workspace browser and file panel

![TODO: add a demo screenshot or GIF for "Unified workspace browser and file panel"](TODO)

Keeping track of what an agent has touched in your repository should not require opening a terminal to run a status check. The workspace panel is now a single, unified browser with a compact file panel, and every file carries a badge marking it as added, modified, or deleted, so you can see the shape of a change at a glance while the agent is still working.

On the desktop, local files gain a Show in Finder action, and an opt-in setting lets you open links from chat in the in-app browser instead of jumping out to your system browser. When an agent or page reaches for something on your local network, you now get a Chrome-style prompt to allow or deny the access.

## 3. Copy-on-write sandbox edits and leaner repository clones

![TODO: add a demo screenshot or GIF for "Copy-on-write sandbox edits and leaner repository clones"](TODO)

Letting an agent experiment freely on a checkout should not mean risking the checkout itself. On Linux, you can now mark a `write_paths` entry with `copy_on_write: true` so the agent's edits land in a disposable layer: the agent sees a fully writable tree, while the underlying files stay exactly as they were once the session ends.

Sandbox startup gets lighter too. Admins can opt into shallow or blobless repository clones so large repositories come up quickly without pulling their full history, and Daytona sessions now keep their workspace intact when a stopped or archived sandbox resumes, so you pick up where you left off instead of starting from a fresh clone.

_Learn more in the [Filesystem](/docs/reference/configuration/os-sandbox#filesystem)._

## 4. Admin defaults for sharing, allowed origins, and Slack setup

![TODO: add a demo screenshot or GIF for "Admin defaults for sharing, allowed origins, and Slack setup"](TODO)

Teams that want every session visible by default should not have to ask each person to flip a switch. From Settings > Sharing, admins can now default new sessions to public, choosing between off, sandbox-only, or all sessions, so the sharing posture matches how your team actually works.

Two more defaults round this out. `OMNIGENT_WS_ALLOWED_ORIGINS` accepts `*.` entries, letting you trust an entire subdomain instead of enumerating every host, and `OMNIGENT_SLACK_DEFAULT_AGENT_ID` and `OMNIGENT_SLACK_DEFAULT_HOST_TYPE` pre-select the agent and managed host for the Slack setup flow, so people connecting from Slack land on your recommended configuration without having to choose.

_Learn more in the [Session sharing](/docs/collaborate/auth#session-sharing)._

## 5. Pi prompt controls and native image passthrough

![TODO: add a demo screenshot or GIF for "Pi prompt controls and native image passthrough"](TODO)

Authoring a tightly scoped Pi agent should not mean fighting the context files Omnigent discovers on your behalf. You can now set `executor.context_files: false` to disable auto-discovered context files entirely, and `executor.system_prompt_mode: replace` to swap out the base prompt for your own rather than layering on top of it, giving you full control over exactly what the model sees.

Visual output also flows through more faithfully. Images returned by MCP tools and screenshots captured by the embedded browser now reach supported harnesses as native images instead of being flattened to text, so your agent can look at a rendered chart or a page it just opened and reason about what it sees.

_Learn more in the [System prompt](/docs/build/prompts#system-prompt)._
