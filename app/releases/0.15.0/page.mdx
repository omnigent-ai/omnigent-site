# v0.15.0

_Released 2026-09-24_ · 4 min read · Omnigent maintainers

Omnigent 0.15.0 is a major release focused on the everyday session experience, from the harnesses and models you launch with to how you compose, branch, and organize your work once a session is running. Devin joins Claude Code and Codex as a native harness, curated model catalogs reach Pi, custom ACP agents, and managed sandbox sessions, and the Composer grows image previews, broader file attachments, and inline control over queued messages and sub-agents. Side chats let you ask a question alongside a session without polluting its context, session management picks up export, manual project ordering, and PR titles, and operators can now serve the whole web UI and API behind a reverse-proxy subpath.

## 1. Devin as a native harness

Running a coding agent through a translation layer means losing the details of its own interface. Devin now runs as a native harness in Omnigent: `omni devin` mirrors the real Devin TUI into the web UI, the same way the Claude Code and Codex native harnesses do, so what you see in the browser is the actual Devin experience rather than an approximation of it.

The previous ACP-based Devin harness is replaced by the native one. The old harness id continues to resolve, but sessions now run through the native path, so existing configurations keep working without changes.

_Learn more in the [Devin](/docs/build/harnesses/configuration#devin)._

## 2. Curated model catalogs for Pi, custom ACP agents, and managed sandboxes

Picking a model should not mean scrolling through every identifier a gateway happens to expose. Pi, custom ACP agents, and managed Kubernetes / Agent Sandbox sessions can now show configured model shortlists, so your team sees the handful of models you actually want them to use.

Catalogs are configured per harness, each with its own gateway, and you can optionally turn on live gateway discovery to populate the list from what the gateway currently serves instead of maintaining it by hand.

_Learn more in the [Choose a model](/docs/build/models#choose-a-model)._

## 3. A richer Composer

<img
  src="/images/releases/0.15.0/skills-composer.png"

  style={{ width: "100%", borderRadius: "8px", margin: "1rem 0" }}

The Composer is where you spend most of your time in a session, and this release makes it do more. You can preview attached images before you send them, and Claude Code and Codex sessions accept more types of files as attachments. Queued messages and active sub-agent work are now managed directly from the Composer, so you can reorder, edit, or check on in-flight work without leaving the input.

Skills are also easier to find: from the new session page, type `/` (or `$` for Codex) to discover and insert the skills available to that session.

_Learn more in the [Multi-modal input](/docs/interact/web-ui#multi-modal-input)._

## 4. Side chats

Sometimes you want to ask a quick question about what the agent is doing without steering the main conversation off course. Side chats give you a separate thread inside your session: the side chat sees the context from your session, but nothing you discuss there is added back to it, so your primary transcript stays focused.

To start one, use the "+" button in the chat pane's right panel.

_Learn more in the [Side questions with `/btw`](/docs/interact/web-ui#side-questions-with-btw)._

You can now export a session straight from its actions menu, arrange projects in the order you want rather than the order they were created, and see pull request titles in the session PR dropdown instead of bare numbers, making it easier to tell at a glance which PR a session is tracking.

_Learn more in the [Session management](/docs/interact/web-ui#session-management)._

## 6. Reverse-proxy subpath deployment with `--base-path`

Not every deployment gets its own hostname. Omnigent can now serve the web UI and API behind a reverse-proxy subpath, so you can mount it alongside other internal tools under a shared domain. Set `OMNIGENT_WEB_BASE_PATH` or pass `omnigent server --base-path` and both the UI and the API resolve correctly under that prefix.
