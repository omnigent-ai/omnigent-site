If you run coding agents that open and update more than one pull request in a
single session, the GitHub tab now keeps track of all of them instead of only
the one on the current branch. You can see the whole list a session has touched
and switch between them, even when they live in different repositories.

Before this, the GitHub rail showed a single pull request inferred from your
branch, so a session that opened a fix in one repo and a follow-up in another
lost sight of the first. Now the session records each pull request as the agent
creates or updates it, and each entry carries its own repository and number, so
the details, changed files, and diff you see always match the pull request you
picked. Recording an association reads from GitHub and never changes the remote
pull request.

Capture is automatic and happens as the agent works, including across compound
`gh` commands, so a chained create-and-comment still tracks the pull request it
created. Simply reading or commenting on a pull request does not link it, which
keeps the list to the ones the session actually worked on. When you want to
correct it, open the GitHub tab in the workspace rail, use the selector to
switch pull requests, and link or unlink one by its URL. See the
[Web UI guide](/docs/interact/web-ui#github) for the tab's controls.
