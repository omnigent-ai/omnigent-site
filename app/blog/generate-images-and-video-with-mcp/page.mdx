## One file to connect it

The example uses [TensorScale](https://tensorscale.io/), which serves image and video
models through an MCP server. (Disclosure: I'm affiliated
with TensorScale.) Omnigent discovers the file automatically:

```yaml
# tools/mcp/tensorscale.yaml
name: tensorscale
transport: http
url: https://mcp.tensorscale.io/mcp
headers:
  Authorization: Bearer ${TENSORSCALE_API_KEY}
timeout: 280
tools: [list_resolutions, text_to_image, text_to_video, get_task_status]
```

The `tools` list does real work here. The server offers many more tools, including
ones that spend credits, and the agent sees only these four.

## Submit once, then poll

Media jobs are asynchronous: `text_to_image` returns a `task_id`, and
`get_task_status` returns the link. Because every submission is billed, the agent's
prompt says to submit once, poll that task, and ask before trying again. The same
rules suit any tool that is slow and costs money.

## Try it

You need a Claude provider, a TensorScale API key and a clone of the Omnigent
repository:

```bash
read -rs TENSORSCALE_API_KEY && export TENSORSCALE_API_KEY
omnigent run examples/media/
```

Then ask for something:

> Make an image of a red paper boat on a calm lake at sunrise.

> Now make a video of the boat drifting across the lake.

Save each file promptly, because the links expire after 15 minutes. Results appear as
links rather than inline media, and the example can't save files to your workspace.

To use another media provider, replace the MCP file and update the tool names in the
prompt. See the
[`media` example](https://github.com/omnigent-ai/omnigent/tree/main/examples/media)
for the full agent and notes on keeping the key safe, and
[MCP & Tools](/docs/build/tools#mcp-servers) for how MCP servers are configured.
